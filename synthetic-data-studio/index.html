Reproducibility

Same seed, same world.

Seed plus configuration plus version produces an identical world — so demonstrations and tests are repeatable.

  • Deterministic seeds. A published seed always regenerates the same entities, events and relationships.
  • Date and geography selection. Authors choose the time window and the Zambian geography a scenario covers.
  • Versioned worlds. Changes publish as new versions; earlier versions stay available for comparison.

Scenarios

From normal conditions to incident — then response.

Scenario authors script coherent storylines; validation checks every world before it publishes.

NORMAL CONDITIONS → WEATHER CHANGE → TRAFFIC EFFECT → ACTIVITY CONCENTRATION → INCIDENT → RELATED EVENTS → RESPONSE

Authors define entities, relationships, timestamps and geography for each beat of the storyline — all synthetic, all labelled.

SCHEMA → TYPES → TIMESTAMPS → GEOGRAPHY → LICENCE → DUPLICATION → INTEGRITY

Validation confirms structure, coherence and labelling before anything publishes. Failed checks return the world to draft with reasons attached.

VERSION → MANIFEST → LICENCE → PUBLISH → ATLAS BOUNDARY

Published worlds cross into Atlas only through the integration boundary — into a synthetic partition, never into live partitions.
